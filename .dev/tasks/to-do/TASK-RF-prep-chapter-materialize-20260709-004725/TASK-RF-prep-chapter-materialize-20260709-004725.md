# Implement /laf:prep Stage 0: Source Materialization (chapter-materialize skill + NATIVE prep-spine wiring)

## Task Overview

The `/laf:prep` pipeline currently requires chapters to be manually pre-split into `source/<slug>/ch-<NN>.txt` before onboarding. This task adds an in-pipeline **Stage 0: Source Materialization** that ingests whatever `--source` resolves to — a folder of per-chapter files (Mode A), a single monolith file (Mode B), or an already-split `source/<slug>/` set (Mode C adopt) — with no manual pre-split, and emits both the canonical `source/<slug>/ch-<NN>.txt` set and a first-class, confidence-tagged `source/<slug>/chapter-manifest.yaml` provenance sidecar. All non-CERTAIN split/mode decisions are routed to the existing human question gate (STAGE 5) and greenlight gate (STAGE 7) — no new gate or HALT machinery is introduced.

The implementation authors ONE new NATIVE skill (`chapter-materialize`: `SKILL.md` + `resources/boundary-rules.yaml`) and edits the NATIVE prep spine (prep-cordinator agent, prep SKILL, `/laf:prep` command, path-contract, source README, VENDOR manifest). It is prompt + YAML authoring only: **ADR-006 forbids adding any script or runtime**; `check_boundary.py` stays the sole script and a validator only, and must remain byte-unchanged. Every hard boundary contract is preserved: the 8-file `00`-`70` package (the manifest is a `source/` sidecar, NOT a 9th numbered file), the frozen 3-file `rewrite_phase_reads`, no adopted-body edit, and a green `check_boundary.py` (baseline already PASSes).

This is a docs/prompt/YAML authoring task derived FROM the driving spec (`merged-requirements.md`), so the final QA includes both an M3 lens-based gate and an M4 source-document fidelity gate (spec → authored artifacts), plus a POST reflect gate.
