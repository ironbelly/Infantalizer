# Create the LAF Adaptation Framework Technical Reference (Standard tier)

## Task Overview

This task produces a comprehensive, code-verified Technical Reference for the **LAF (Literary Adaptation Framework)** located at `/config/workspace/Infantalizer/laf-adaptation/`. LAF is a prompt + YAML-config framework (NOT software, per ADR-006) for tier-aware literary adaptation: it takes a source novel and produces developmentally-graded adaptations across Tiers 1/2/3/5 (T4 interpolated) via two pipelines (prep → rewrite), a multi-agent review workflow, a native knowledge-base (kb) layer, and a hash-pinned boundary contract that keeps a vendored CWS (creative-writing-skills) subset patch-clean.

The final document is written to `/config/workspace/Infantalizer/docs/laf/LAF-ADAPTATION-FRAMEWORK-TECHNICAL-REFERENCE.md` and MUST conform to the project template at `/config/.claude/templates/documents/technical_reference_template.md`. The task follows the Rigorflow multi-phase pipeline: deep investigation (6 parallel codebase research agents) → research completeness gate → optional web research → synthesis (5 agents) → synthesis gate → assembly → lens-based QA gate → source-document fidelity gate → present and complete. Every phase gate runs at **standard** QA intensity (per Template 02 I22).

Because LAF is a prompt+YAML framework with no client-side runtime state and no UI components, template §6 (State Management) and §7 (Component Inventory) are marked **N/A** with rationale, and §11 (Performance) is a short note (agent-parallelism / token shape) rather than a measured profile. A known documentation-staleness item is pre-identified and MUST be surfaced (not resolved away): `laf-adaptation/CLAUDE.md` §1 states "15 agent files" and "16 skill dirs", but the live tree has **16 agents and 18 skills** — this is doc-vs-doc drift recorded in Tech Debt (§14) tagged `[CODE-CONTRADICTED]`, NOT a C8 unwired-capability defect.
